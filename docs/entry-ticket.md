# 10/4 整理券発行システム（entry/・kanrishi/）

2026年10月4日（日）日本レセプト学会 学術研究会（昭和女子大学）で配布する整理券をWebで発行する仕組み。2つの制度で同じ動線を使う。

| 制度 | 申込ページ（QRコード） | 整理番号 | シート（整理券／キャンセル待ち） |
|---|---|---|---|
| 病院向けAI研修 | `https://www.iha-as.com/entry/` | `001`〜`050` | `1004_整理券`／`1004_キャンセル待ち` |
| 医療AIガバナンス管理士（個人認定） | `https://www.iha-as.com/kanrishi/` | `K-001`〜`K-050` | `1004_管理士_整理券`／`1004_管理士_キャンセル待ち` |

Apps Script（Web アプリ）は1本で両制度を処理する。ページは送信時に `program`（`hospital`／`kanrishi`）を送り、未指定は `hospital` として扱う。

## 構成

                       ▼

## 仕様

### 整理番号と確認コード
- 整理番号：連番。病院向けは `001`〜、管理士は `K-001`〜（受付で種類を取り違えないよう頭文字で区別）
- 確認コード：英数字4文字（読み間違えやすい 0/O・1/I/L・2/Z・5/S・6/G・8/B は不使用）。**両制度を通して重複なし**
- 受付・問い合わせでは **整理番号＋確認コード** で照合する
- 番号とコードは `setupTickets` 実行時に事前作成。当日追加した行は発行時にコードを自動生成
- 管理士の完了画面・メールには制度名「医療AIガバナンス管理士」を表示

### 両制度の関係
- 同じ人（同じメール）が両方に申し込める（それぞれ別の番号が出る）
- 受付停止は全体（`ACCEPTING`）または制度別（`ACCEPTING_HOSPITAL`／`ACCEPTING_KANRISHI`）

### キャンセル待ち
- 定員到達後の申込は各制度のキャンセル待ちタブに追加し「キャンセル待ち N番目」を表示・メール送信
- 受付順は通し番号（繰り上がっても振り直さない）
- 枠を追加（整理券タブ末尾に番号行を追加）すると、以降の申込者から順に発行。キャンセル待ちの人が再送信した場合は整理券を発行し、待ち側の状態を「整理券発行済（番号）」に更新

### 重複・同時申込
- 同じメールアドレスは同じ番号（またはキャンセル待ちの受付順）を再表示。確認メールは再送しない
- 「登録済み確認 → 空き番号検索 → 書き込み」をスクリプトロック内で一括実行。同時申込は到着順に1件ずつ処理され、番号の二重発行・定員超過の発行は起きない
- 外部通信（DNS・メール）はロック外。ロック待ちは最大20秒、超えた場合は「混み合っています」を表示し再送信で処理
- 通信エラーで番号が表示されなかった場合も、同じメールで再送信すれば同じ番号を表示
- 整理券タブが無い（`setupTickets` 未実行）ときは「受付準備中です」を返す

### メールの誤入力・到達確認
1. **確認画面**：送信前にメールアドレスを大きく表示して本人に確認させる
2. **形式チェック**：先頭が英数字でないアドレス（`=`・`+`・`-` 始まり等）は不可（シートで数式扱いになるのを防ぐ）。全角「＠」は半角に変換
3. **打ち間違いドメイン**：`gmial.com`・`yahoo.co.jo`・`docomo.ne.jo` など、実在するため DNS チェックを通ってしまう代表的な誤記を「@gmail.com の誤りではありませんか？」と案内（一覧は `TYPO_DOMAINS`）
4. **ドメイン実在チェック**：存在しないドメインは送信時にエラー。DNS 照会自体が失敗した場合は申込を止めない
5. **到達確認**：Resend 経由で送信し、5分ごとに配信結果を取得

| 到達状況 | 意味 | 対応 |
|---|---|---|
| 送信中 | 送信処理中 | 待つ |
| 到達 | 相手のメールサーバーが受信（開封・迷惑フォルダかは問わない） | 不要 |
| 遅延中 | 相手サーバー側で配送遅延 | 次回確認で更新 |
| 不達 | アドレスが存在しない等で届かなかった | 氏名・所属から別手段で連絡 |
| 迷惑メール報告 | 受信者が迷惑メールと報告 | 状況確認 |
| 確認不可（Gmail送信） | Resend 未設定／失敗により Gmail で送信 | 到達は確認できない |

- Resend の重複送信防止キーには発行日時を含める。テストデータ消去後に同じ番号・同じアドレスで再テストしてもメールが送られる

### シートの列（4タブ共通の並び）

整理券タブ：整理番号／確認コード／状態／受付日時／氏名／所属施設／メールアドレス／メール送信／到達状況／メールID
キャンセル待ちタブ：受付順／確認コード／状態／受付日時／氏名／所属施設／メールアドレス／メール送信／到達状況／メールID／対応メモ（手入力用）

## セットアップ

### A. Resend（送信ドメインの認証）

1. https://resend.com でアカウント作成
2. **Domains → Add Domain** で `iha-as.com` を追加
3. 表示された DNS レコード（MX・TXT〔SPF〕・TXT〔DKIM〕）を、`iha-as.com` の DNS 管理画面に**表示どおり**追加（サイト向けの既存レコードは変更しない）
4. **Verify** → Status が `Verified` になるまで待つ（通常数分〜数時間）
5. **API Keys → Create API Key**（権限：**Full access**。Sending access では到達状況を取得できない）

> **通数に注意**：無料プランは **1日100通**。2制度×50名＋キャンセル待ち＋テストで 10/4 当日に100通を超える可能性がある。超過分は Resend がエラーを返し、自動で Gmail 代替送信になる（到達状況は「確認不可」）。全件で到達確認したい場合は、10月だけ Pro プラン（月$20・日次上限なし）に上げる。

> Resend が間に合わない場合は A・C の Resend 設定を飛ばしてよい（Gmail 送信・到達確認なしで動く）。

### B. Apps Script の更新（既存プロジェクト `entry-ticket`）

新規作成ではなく、**稼働中のプロジェクトを更新**する（URL を変えないため）。

1. https://script.google.com → `entry-ticket` を開く
2. `コード.gs` を `google-apps-script/entry-ticket.gs` の内容で**全置換**して保存
3. 「プロジェクトの設定」→「"appsscript.json" マニフェスト ファイルをエディタで表示する」をオン → `appsscript.json` を `google-apps-script/appsscript.json` の内容で置換して保存
4. 関数 `setupTickets` を実行 → 権限の再承認を求められたら許可（トリガー用の権限が増えたため）
   - 既存の `1004_整理券`／`1004_キャンセル待ち` は**変更されない**（ログに「スキップ（既存）」）
   - `1004_管理士_整理券`（K-001〜K-050＋確認コード）と `1004_管理士_キャンセル待ち` が作成される
5. 「デプロイ」→「デプロイを管理」→ 既存デプロイの鉛筆 → バージョン「**新バージョン**」→「デプロイ」
   - 「新しいデプロイ」は URL が変わるので使わない
6. Web アプリ URL をブラウザで開き、`"programs":{"hospital":{…},"kanrishi":{"accepting":true,"total":50,…}}` を確認

### C. スクリプトプロパティ（Resend 利用時）

| プロパティ | 値 |
|---|---|
| `RESEND_API_KEY` | A-5 の API キー |
| `MAIL_FROM` | `国際ヘルスケアAI管理推進協会 <noreply@iha-as.com>` |
| `ASSOCIATION_REPLY_TO` | 返信先（協会の問い合わせアドレス） |
| `ACCEPTING` ／ `ACCEPTING_HOSPITAL` ／ `ACCEPTING_KANRISHI` | （受付停止時のみ）`false` |

設定後：
1. `testResendMail` の宛先を自分のアドレスに書き換えて実行 → 届くこと、ログに `"deliv":"送信中"` と ID が出ること
2. `installDeliveryTrigger` を1回実行（5分ごとの到達確認を登録）

### D. サイト側

`kanrishi/index.html` を追加（`TICKET_API_URL` は `entry/index.html` と同じ URL を設定済み）。`entry/index.html` は変更不要。

### E. 本番前テスト（必須）

管理士（`https://www.iha-as.com/kanrishi/`）：
1. 入力 → 確認 → `K-001`＋確認コード＋「医療AIガバナンス管理士」表示
2. `1004_管理士_整理券` に記録／確認メール受信（件名【整理番号 K-001】医療AIガバナンス管理士 整理券…）
3. 同じメールで再送信 → 同じ番号＋「登録済み」、メールは再送されない
4. `test@gmial.com` → 「@gmail.com の誤りではありませんか？」で入力画面に戻る
5. `test@no-such-domain-iha-as.com` → 「ドメイン…が見つかりません」
6. キャンセル待ち：`1004_管理士_整理券` の K-002〜K-050 の「状態」に一時的に「発行済」→ 送信 →「キャンセル待ち 1番目」

病院向け（回帰確認）：
7. `https://www.iha-as.com/entry/` で1件送信 → `001` 系の番号が出て `1004_整理券` に記録される（管理士タブに入らない）

Resend 利用時：
8. 5〜10分後、「到達状況」が「到達」になる

後片付け：
9. 整理券タブ（2つ）の C〜J 列（状態〜メールID）を消去（A・B 列は残す）、キャンセル待ちタブ（2つ）の2行目以降を行削除
10. Web アプリ URL で両制度とも `used:0`／`waiting:0` を確認

## 当日運用

- QR コード：病院向け `https://www.iha-as.com/entry/`、管理士 `https://www.iha-as.com/kanrishi/`（**パネル・QRに制度名を明記**して取り違えを防ぐ）
- 受付での照合：申込者の画面（またはメール）の **整理番号＋確認コード＋氏名** をシートで確認（Ctrl+F で確認コード検索。コードは両制度で重複しない）
- 整理番号の頭文字：`K-` 付き＝管理士、数字のみ＝病院向け
- 「メールが届かない」と言われたら：迷惑メールフォルダ確認 → シートの到達状況を確認 → 不達ならその場で正しいアドレスを聞き「対応メモ」等に記録
- 残数確認：エディタで `showRemaining`（制度別に表示）、または Web アプリ URL（`programs`）
- 枠を増やす：該当の整理券タブ最終行の下に番号を追加（管理士は `K-051`…。確認コードは空欄で可）
- 受付停止：`ACCEPTING_KANRISHI` / `ACCEPTING_HOSPITAL` / `ACCEPTING` = `false`（即時反映）

### 注意
- 受付中は、シートの「状態」〜「メールID」列を手で書き換えない（ロックの外からの変更になるため）。番号行の末尾追加・「対応メモ」の入力は可
- メール通数の上限（Resend 無料 1日100通、無料 Gmail 1日100通）に注意
