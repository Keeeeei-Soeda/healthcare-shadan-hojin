# 10/4 整理券発行システム（entry/）

2026年10月4日（日）日本レセプト学会 学術研究会（昭和女子大学）で配布する、病院向けAI研修の整理券をWebで発行する仕組み。

## 構成

```
[受付パネルのQRコード]
        │
        ▼
https://www.iha-as.com/entry/        … GitHub Pages（entry/index.html）
  1. 入力（担当者名・所属施設・メール）
  2. 確認（メールアドレスを大きく表示）
  3. 整理番号＋確認コードを表示
        │ POST（JSON / text/plain）
        ▼
Apps Script Web アプリ（entry-ticket.gs）
  ├ ドメイン実在チェック …… Google Public DNS
  ├ 番号割当（ロック内で1件ずつ）
  │    ├ 空きあり → 整理番号＋確認コード
  │    └ 満了     → キャンセル待ち（受付順＋確認コード）
  ├ スプレッドシートに記録 …… タブ「1004_整理券」「1004_キャンセル待ち」
  └ 確認メール送信 …………… Resend（noreply@iha-as.com）
                               失敗・未設定時は Gmail で代替送信
        ▲
        │ 5分ごと（時間トリガー）
checkDelivery() …… Resend から配信結果を取得 →「到達状況」列を更新
```

| ファイル | 役割 |
|---|---|
| `entry/index.html` | 申込フォーム（入力 → 確認 → 整理番号）。noindex・サイト内リンクなし |
| `google-apps-script/entry-ticket.gs` | 番号割当・記録・メール送信・到達確認 |
| `docs/entry-ticket.md` | 本書 |

## 仕様

### 整理番号と確認コード
- 整理番号：連番（001〜）。先着順・当日の呼び出し用
- 確認コード：英数字4文字（読み間違えやすい 0/O・1/I/L・2/Z・5/S・6/G・8/B は不使用）。全員で重複なし
- 受付・問い合わせでは **整理番号＋確認コード** で照合する（番号の聞き間違い・なりすまし防止）
- 番号とコードは `setupTickets` 実行時にシートへ事前作成。当日追加した行は発行時にコードを自動生成

### キャンセル待ち
- 定員到達後の申込は「1004_キャンセル待ち」に追加し「キャンセル待ち N番目」を表示・メール送信
- 受付順は通し番号（繰り上がっても振り直さない）
- 枠を追加（整理券タブ末尾に番号行を追加）すると、以降の申込者から順に発行。キャンセル待ちの人が再送信した場合は整理券を発行し、待ち側の状態を「整理券発行済（番号）」に更新

### 重複・同時申込
- 同じメールアドレスは同じ番号（またはキャンセル待ちの受付順）を再表示。確認メールは再送しない
- 「登録済み確認 → 空き番号検索 → 書き込み」をスクリプトロック内で一括実行。同時申込は到着順に1件ずつ処理され、番号の二重発行・定員超過の発行は起きない
- 外部通信（DNS・メール）はロック外。ロック待ちは最大20秒、超えた場合は「混み合っています」を表示し再送信で処理
- 通信エラーで番号が表示されなかった場合も、同じメールで再送信すれば同じ番号を表示

### メールの誤入力・到達確認
1. **確認画面**：送信前にメールアドレスを大きく表示して本人に確認させる
2. **ドメイン実在チェック**：存在しないドメイン（例 `@gmial.com`）は送信時にエラー。DNS 照会自体が失敗した場合は申込を止めない
3. **到達確認**：Resend 経由で送信し、5分ごとに配信結果を取得

| 到達状況 | 意味 | 対応 |
|---|---|---|
| 送信中 | 送信処理中 | 待つ |
| 到達 | 相手のメールサーバーが受信（開封・迷惑フォルダかは問わない） | 不要 |
| 遅延中 | 相手サーバー側で配送遅延 | 次回確認で更新 |
| 不達 | アドレスが存在しない等で届かなかった | 氏名・施設から別手段で連絡 |
| 迷惑メール報告 | 受信者が迷惑メールと報告 | 状況確認 |
| 確認不可（Gmail送信） | Resend 未設定／失敗により Gmail で送信 | 到達は確認できない |

### シートの列

`1004_整理券`：整理番号／確認コード／状態／受付日時／氏名／所属施設／メールアドレス／メール送信／到達状況／メールID
`1004_キャンセル待ち`：受付順／確認コード／状態／受付日時／氏名／所属施設／メールアドレス／メール送信／到達状況／メールID／対応メモ（手入力用）

## セットアップ

### A. Resend（送信ドメインの認証）

1. https://resend.com でアカウント作成（無料プラン：1日100通・月3,000通）
2. **Domains → Add Domain** で `iha-as.com` を追加
3. 表示された DNS レコード（MX・TXT〔SPF〕・TXT〔DKIM〕）を、`iha-as.com` の DNS 管理画面に**表示どおり**追加
   - サイト（GitHub Pages）向けの既存レコードは変更しない
4. Resend 画面で **Verify** → Status が `Verified` になるまで待つ（通常数分〜数時間）
5. **API Keys → Create API Key**（権限：**Full access**。Sending access では送信はできるが、到達状況の取得ができない）→ キーを控える

> Resend が間に合わない場合は、A・C の Resend 設定を飛ばしてよい。Gmail で送信され、到達状況は「確認不可」になる。

### B. Apps Script（お問い合わせ用とは別プロジェクト）

1. スプレッドシート（`190L3DfU…`）を編集できる協会アカウントで https://script.google.com →「新しいプロジェクト」→ 名前 `entry-ticket`
2. `コード.gs` を `google-apps-script/entry-ticket.gs` の内容で置き換えて保存
3. 関数 `setupTickets` を実行 → 権限を承認（「詳細」→「entry-ticket（安全ではないページ）に移動」→「許可」）
   - スプレッドシートに `1004_整理券`（001〜050＋確認コード）と `1004_キャンセル待ち` ができる

### C. スクリプトプロパティ（プロジェクトの設定 → スクリプト プロパティ）

| プロパティ | 値 |
|---|---|
| `RESEND_API_KEY` | A-5 の API キー |
| `MAIL_FROM` | `国際ヘルスケアAI管理推進協会 <noreply@iha-as.com>` |
| `ASSOCIATION_REPLY_TO` | 返信先（協会の問い合わせアドレス） |
| `ACCEPTING` | （受付停止時のみ）`false` |

設定後：
1. `testResendMail` の宛先を自分のアドレスに書き換えて実行 → 届くこと、ログに `"deliv":"送信中"` と ID が出ること
2. `installDeliveryTrigger` を1回実行（5分ごとの到達確認を登録）

### D. Web アプリとしてデプロイ

1. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
2. 次のユーザーとして実行：**自分** ／ アクセスできるユーザー：**全員**
3. 発行された `https://script.google.com/macros/s/…/exec` を控える
4. その URL をブラウザで開き `{"ok":true,"service":"entry-ticket",…,"resend":true}` を確認

> 以後コードを直したら「デプロイを管理」→ 鉛筆 → バージョン「新バージョン」→「デプロイ」。URL は変わらない（「新しいデプロイ」は URL が変わるので使わない）。

### E. サイト側

`entry/index.html` の `TICKET_API_URL` を D-3 の URL に置き換えて push。

### F. 本番前テスト（必須）

1. スマホで `https://www.iha-as.com/entry/` → 入力 → 確認 → 番号＋確認コード表示
2. シートに記録／確認メール受信（件名【整理番号 001】…、本文に確認コード）
3. 5〜10分後、「到達状況」が「到達」になる
4. 同じメールで再送信 → 同じ番号＋コード＋「登録済み」表示、メールは再送されない
5. `test@gmial.com` で送信 → ドメインエラーで入力画面に戻る
6. キャンセル待ち：`1004_整理券` の001〜050の「状態」に一時的に「発行済」を入れて送信 → 「キャンセル待ち 1番目」
7. **後片付け**：`1004_整理券` の C〜J 列（状態〜メールID）を消去（A・B 列は残す）、`1004_キャンセル待ち` の2行目以降を行削除

## 当日運用

- QR コード：`https://www.iha-as.com/entry/`
- 受付での照合：申込者のスマホ画面（またはメール）の **整理番号＋確認コード＋氏名** を、シートで確認（Ctrl+F で確認コード検索が速い）
- 「メールが届かない」と言われたら：迷惑メールフォルダ確認 → シートの到達状況を確認 → 不達ならその場で正しいアドレスを聞き、「対応メモ」等に記録
- 残数確認：エディタで `showRemaining`、または Web アプリ URL を開く（`used`／`total`／`waiting`）
- 枠を増やす：`1004_整理券` の最終行の下に `051`… を追加（確認コードは空欄で可、発行時に自動生成）
- 受付停止：スクリプトプロパティ `ACCEPTING` = `false`（即時反映）

### 注意
- 受付中は、シートの「状態」〜「メールID」列を手で書き換えない（ロックの外からの変更になるため）。番号行の末尾追加・「対応メモ」の入力は可
- Resend 無料プランは1日100通。50名＋キャンセル待ちなら十分だが、テスト送信の通数にも注意
- 無料 Gmail で代替送信となった場合も1日100通まで

## イベント終了後
- `ACCEPTING` = `false` で受付停止、`removeDeliveryTrigger` を実行
- `entry/` はリンクされていない noindex ページ。不要になれば削除
